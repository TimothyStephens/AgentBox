# agentbox

`agentbox` (`ab`) runs a coding agent — **Claude Code** or **OMP** — inside a hardened, throwaway rootless
podman sandbox on this host, scoped to a single project, with explicit grants for directories, pods and
network destinations. The hardening lives in the launcher and on the host side, so swapping the agent never
weakens it.

## What it does

- A stray `rm -rf` or an over-eager "fix" can only touch what the session was granted; the rest of the host
  is not mounted.
- Projects never see each other — files, agent state, caches, networks and pods are per-project and
  per-session.
- The grant holds **code**; secrets and live data stay outside it, and a session refuses to start if it finds
  an uncovered secret or a live database in the grant.
- Network egress is an allowlist proxy, set per project (`locked` / `packages` / `open`); the LAN and host
  services are never reachable.
- The agent can run its own container stacks, install packages and use a browser — all within those bounds,
  and every container it starts is pinned to the session network and proxy.
- Every boundary is checked by `ab selftest`, not assumed.

## What it does **not** do

- It is **not** a defence against a deliberately malicious or prompt-injected agent trying to break out or
  exfiltrate. On a shared kernel, as rootless `vmuser`, a determined adversary has too many channels; the
  controls raise the cost of an **accident** and of cross-project movement, they are not a VM jail.
- It does not stop a kernel or runtime escape (a container is not a VM boundary), nor deferred execution
  (code the agent writes and you later run executes as you).
- Several commands and tiers are **planned, not built** (`ab ws`, `ab deploy`, `ab attach`, the key gateway,
  the podman `exec` tier, Pi/Codex adapters). `docs/progress.md`'s Status table is the authoritative
  built / deferred / not-built list.

## How it works, in one paragraph

One launcher calls podman; nothing else does. `ab run` builds a session — its own internal network, an
allowlist squid proxy, a per-project agent container (`--cap-drop=ALL`, read-only root, keep-id, under a
cgroup slice) — and the agent's only two ways out are the squid proxy for the network and a filtered podman
socket for containers (the **two host-side gates**). The real `.env` is masked (the agent sees `.env.dev`),
`secrets/` and `.git` config are covered, and the grant is backed up before the session so a mistake can be
undone. On exit everything the session created is torn down, keeping only logs, a change scan, and the backup.

## Install

See **[docs/INSTALL.md](docs/INSTALL.md)** for prerequisites, the steps, and exactly where everything lands.
In short:

```bash
make install-slice          # the cgroup slice
make claude-image omp-image # the session images (bases must exist)
make install                # ab + agentbox on PATH
ab keys rotate claude       # a model credential
ab init pod --name demo     # scaffold + register a project, then: ab run claude demo
```

## Tests

- `make test` — fast unit checks, no podman.
- `make itest` — real podman, `abt-` names, cleans up after itself; warns when `make claude-live` needs
  rerunning.
- `make claude-live`, `make omp-live` — run by you, with your real token, keys and `~/.omp`.
- `make verify-sockguard` — checks the pinned sockguard image's signature (needs cosign).
