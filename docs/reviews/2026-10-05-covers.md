## Gaps, ranked

**H1. Renaming a cover's parent directory moves the cover out of reach of a path-based check.**
- **Check first:** in `/tmp`, run `unshare -rm sh -c 'mkdir -p a/b; mount --bind /tmp/x a/b; mv a c && echo RENAMED'`.
- **Fix:**
  - In the agent's container, bind every directory between the grant root and each cover onto itself, so renaming any of them fails with EBUSY. Renames across those boundaries will fail with EXDEV; for example, `git mv dev/x app/` will break. Record that in decisions.md.
  - In the gate, record each cover's (st_dev, st_ino) at session start, stop calling `realpath` on it again, and refuse every grant bind if any cover's identity has changed.
- **Test to add (itest):** as the agent, `mv dev dev2`, then `podman run -v $ROOT/dev2:/d … cat /d/.env` must not print the sentinel. Do the same for `mv .git .g` followed by a write to `/g/config`. Add a variant where a container is already running with `app/` bound and the agent then runs `mv dev app/dev`.

**H2. The after-start check comes too late for a swapped sub-path, and fails open if the container has exited.**
- **Fix:** for start, restart and pod start, have the gate call `POST /libpod/containers/{id}/init` first (sockguard already allows it). The runtime then has its mounts in place but hasn't run the entrypoint. Check `/proc/<pid>/mountinfo`, and only then forward `start`. Treat a missing PID or unreadable mountinfo as a refusal. Handle restart as stop, init, check, start.
- **Test to add (itest):** create a container with `app` as a sub-path, replace `app` with a symlink to `secrets`, start it running `cat /a/db-password.txt`, and assert the sentinel never appears in logs or in a shared volume. Add a unit test that `mount_violations` refuses when the PID is 0 or reading mountinfo raises `OSError`.

**H3. A read-only grant can be bound read-write.**
- **Fix:** keep a set of read-only grant roots. Force `ro` on binds from them, and on grant-volume mounts over them. After start, refuse if the mount flags in mountinfo show `rw`.
- **Test to add:** `podman run -v $DATA_RO:/d … touch /d/x` must fail.

**M1. The test passes for the wrong reason, and coverage is thin.**
- In `test_step6_covers.py`, the HOOKSPATH probe writes to `/a/../.git/config`. Inside the container that path is `/.git/config`, which doesn't exist, so the probe fails no matter what the gate does. It proves nothing.
- Missing cases:
  - the dev-swap `.env` when `.env.dev` exists (`CoveredPaths` doesn't test the `dst != src` branch either)
  - `.git/config.worktree`
  - compose covers and lockdown covers
  - a nested mask such as `sub/.env`
- **Fix:** replace HOOKSPATH with the H1 `.git` rename case, and add the cases above.

**L1. Covers are path-based, so a hardlink made before the session is not hidden.** Spec §4.4 says covers must hide data "including via … a hardlink". If a masked file is also linked under another name, that name is readable even inside the agent's container. This predates the commit. Note it in the spec, or check `st_nlink > 1` when planning the mounts.

**L2.** Add a test that naming `<session>-grant0` directly in `volumes` with a covered SubPath is refused.

**L3.** Add image `get`/`export` to the gate's DENIED list so they don't rely on sockguard alone.

**L4.** Add a build test whose Containerfile COPYs `secrets/` and `.env` and checks that both arrive empty, so a later change to how build contexts are produced can't slip by. Separately, `RUN --mount=type=cache` uses a cache shared across builds on this host user. That's not a cover issue, but it's worth an item in Open items.

## Doc claims the fix doesn't back up
- **`session.py:272` (shown to the agent) and the decisions.md entry** say "These covers, and the masks below, are enforced for containers you start too". That's not true while H1 and H2 are open.
- **decisions.md** says the after-start mountinfo check "refuses" a SubPath that a swap redirected onto a cover. It does remove the container, but only after the entrypoint has run, and never if the container has already exited.
- **decisions.md and the `covered_paths` docstring** say "a read-only grant is not a cover", which suggests the read-only grant is still read-only in spawned containers. It isn't (H3).
- **decisions.md** says a `masked_paths` setting "needs no further gate work". It does: `data/` is a typical nested mask, which is exactly the shape H1 breaks.
- **The decisions.md test list** claims `.git/config` is shown read-only for spawned containers. The probe that should show it (HOOKSPATH) doesn't test it (M1); only the direct-bind refusal does.
