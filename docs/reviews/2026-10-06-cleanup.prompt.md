Read-only maintainability audit of the agentbox codebase. Make NO edits and start no containers.
Read CLAUDE.md, docs/design.md and docs/progress.md for what the tool is meant to do, then the code
and tests. Produce a report (write it to docs/reviews/2026-10-06-cleanup.md), not changes.

First, classify every module as ENFORCEMENT (gate.py, grantcheck.py, sockguard.py, the mount/cover/pin
logic in session.py and mounts.py, hardening) or SUPPORT (cli, init, adapters, presets, helpers).

Then report, each item tagged with file:line and its module class:
1. Test coverage — run the coverage tool (pytest --cov or coverage run) and report. List every
   UNCOVERED line/branch in ENFORCEMENT code first and most prominently; those are latent holes, not
   style. Then uncovered support code. Give the overall number but lead with the enforcement gaps.
2. Genuinely dead code — functions, parameters, config keys, imports, vars with NO caller/reader.
   For anything in ENFORCEMENT, prove deadness (no caller, no test, no dynamic dispatch reaches it)
   and mark removal as "needs sign-off"; do not assume an enforcement guard is dead because it rarely
   fires. (Known example to check: a caps/devices opt-in stored in presets but never read.)
3. Redundancy / duplication — the same check or logic implemented in two places that could drift
   apart. In enforcement, duplication is sometimes deliberate defence in depth; flag it, don't assume.
4. Transitional cruft from many iterations — commented-out blocks, TODO/FIXME, half-removed features,
   dead branches behind flags that are always one value, superseded helpers.
5. Over-complexity / verbosity — functions doing too much, needless indirection, parameters that are
   always passed the same value. Flag for SUPPORT code; for ENFORCEMENT, only note it, don't propose
   behavioral rewrites.
6. Comments and docstrings that are now WRONG after iterations (lying comments are worse than none) —
   list each with the correct statement.
7. Test quality, not just coverage — tests that assert nothing, test the mock, or would pass even if
   the guard were removed (especially in enforcement). Name them.

Rank everything by: enforcement-coverage gaps (highest), then wrong comments/docstrings, then dead
support code, then cosmetic. For each proposed removal say what proves it's safe to remove. Do not
propose any enforcement behavior change; this pass only finds and documents.
