I've written the audit below. I didn't edit any files or start any containers, so everything here comes from reading the code. One high finding depends on podman behaviour I couldn't run; it's marked, with a command you can run to settle it.

**Bottom line:** for secrets, grantcheck isn't an independent wall. It uses the same four name patterns as the masks (`grantcheck.py:25` vs `mounts.py:11`), and it skips whatever the masks skip (`mask_skip`, the `WALK_SKIP` dirs, symlinks). So anything the masks miss, grantcheck misses too. Its own catches are only: covers that are switched off, git URLs with `user:pass@`, sqlite over 1 MB, and compose binds of directories holding `.db` files. And the gate-spawned container makes one gap worse than in the agent's own namespace (H1).

## High

**H1. Data dirs unreadable to the scanner are open to a gate-spawned container (shape 14). Needs checking.**
- A rootless Postgres, MySQL or Redis container leaves its bind dir owned by a subuid (e.g. 100998) with mode 0700.
  - grantcheck's `os.walk` (`grantcheck.py:107`, `:88`) has no `onerror`, so the dir scans clean.
  - `secret_mounts`, `hardlink_masks` and the gate's `unmasked_secret_under` (`gate.py:604`) are blind to it the same way.
  - The agent itself can't read it (keep-id, `--cap-drop=ALL`, `session.py:776`).
- The gate does let the agent run a container as root (default capabilities, including DAC_OVERRIDE inside the user namespace) or with `user: 999`, and bind `$ROOT` or `$ROOT/pgdata`. The bind becomes a grant-volume SubPath (`gate.py:1397`).
  - That container reads the live database, and can write to it.
  - The `U`/`chown` mount options are allowed (`gate.py:270`, `:274`), so it can also re-own the live data dir.
  - Worst case: the agent's dev compose starts a second postmaster on the live `pgdata`.
- This may be the very shape behind Track 1 ("reach a repo-local database from a container it started"). If that database was a container's data dir, the current scan would not have flagged it.
- **Check (you run this; it uses `/tmp` and the label):**
  ```
  mkdir -p /tmp/abt-h1/pgdata && echo SENTINEL > /tmp/abt-h1/pgdata/s
  podman unshare chown -R 999:999 /tmp/abt-h1/pgdata && podman unshare chmod 700 /tmp/abt-h1/pgdata
  python3 -c 'from agentbox import grantcheck as g; print(g.scan("/tmp/abt-h1",["/tmp/abt-h1"]))'   # [] today
  podman run --rm --label agentbox-test=1 -v /tmp/abt-h1/pgdata:/d busybox:1.36 cat /d/s          # SENTINEL?
  ```
- **Fix:**
  1. In grantcheck, report any directory or file in a grant that isn't owned by `getuid()` or can't be read ("owned by uid N / unreadable: a container's data dir?"), using `os.walk(onerror=…)` plus an `st_uid` check.
  2. In the gate's bind-time walk, refuse sources with foreign-owned or unreadable entries, and refuse `U`/`chown` on grant binds and grant SubPaths.
- **Tests:**
  - Unit `test_grantcheck`: a `chmod 000` subdir gives a finding; a fake `st_uid` gives a finding.
  - Gate unit: a SubPath bind over a dir with foreign uid is denied, and `U` is denied.
  - Itest in `test_step6_covers`: seed a fixture `pgdata/` with `podman unshare chown 999:999` and the ack recorded. From the session, run `podman run -v $ROOT/pgdata:/d busybox:1.36 cat /d/s` and the same with `--user 999` and `-v $ROOT:/r`. Assert the gate's 403, not "Permission denied", and no `SENTINEL`.

**H2. For secrets, the "primary wall" is the cover's own name list (shapes 4, 5, 16).**
- Every secret that isn't named `.env*`/`*.pem`/`*.key`/`secrets/` passes both layers, in read-write and read-only grants: a DSN in `config/prod.yaml`, `deploy/id_ed25519`, `terraform.tfstate`, `.npmrc`.
- **Fix:**
  - Widen the shared name list in both modules: `id_*` without `.pub`, `*.p12`/`*.pfx`/`*.jks`/`*.keystore`/`*.kdbx`, `.netrc`, `.npmrc`, `.pypirc`, `.git-credentials`, `*.tfstate*`, `credentials*.json`, `*service-account*.json`, `kubeconfig`, `.htpasswd`.
  - Add a **content** check to grantcheck, so it stops depending on names. Scan text files under 1 MB for high-confidence shapes: `-----BEGIN [A-Z ]*PRIVATE KEY-----`, `AKIA[0-9A-Z]{16}`, `gh[pousr]_[A-Za-z0-9]{36}`, `github_pat_`, `xox[abpr]-`, `sk-ant-`, and `scheme://user:pass@` in *any* file.
  - Report hits whether or not the name is covered.
- **Tests:**
  - Unit: `config/settings.yaml` holding `postgres://app:pw@db/app`, `deploy/id_ed25519` holding a PEM header, and `infra/terraform.tfstate` each give a finding.
  - Session test: a project with `config/prod.yaml` holding a fake `sk-ant-` token refuses to start.

**H3. `mask_skip` turns off both layers, and the refusal message offers it as the fix (shape 3).**
- `message()` (`grantcheck.py:145`) says "mask_skip excludes a path". Adding it makes the finding disappear with no ack, and leaves the file unmasked as well as unscanned.
- `test_mask_skip_excludes` (`test_grantcheck.py:53`) asserts exactly this behaviour.
- The design defines `mask_skip` as a speed knob for huge trees, not an exemption.
- **Fix:**
  - grantcheck ignores `mask_skip`, or scans those folders and reports secret-named files there as "unmasked (mask_skip)".
  - Remove `mask_skip` from the message's suggested remedies.
- **Test:** invert `test_mask_skip_excludes`. A 2 MB `vendor/big.db` and a non-empty `vendor/.env` with `mask_skip=["vendor"]` both give findings; the message text doesn't contain `mask_skip`.

## Medium

**M1. Live-data detection is a suffix-and-size list (shapes 8–13).**
- **Fix:**
  - Detect sqlite by its magic bytes (`SQLite format 3\0`) at any non-zero size, and include `-wal`/`-journal`.
  - Add dump and engine markers: `*.sql(.gz)`, `*.dump`, `dump.rdb`, `*.aof`. A dir containing `PG_VERSION`, `ibdata1` or `*.wt` is a database.
  - Read compose files matching `*compose*.y*ml`.
  - Flag every compose bind source inside the grant that holds no git-tracked files: tracked means code, untracked or ignored means data. That also catches pgdata without parsing it.
- **Tests:** unit cases for each shape: a 200 KB db, a WAL alone, `backup.sql`, a `pgdata/` with a `PG_VERSION` file, a bind in `docker-compose.override.yml`, and an untracked `./uploads` bind.

**M2. `data_ro` is never scanned (shapes 2, 22).**
- `history_secrets` does scan `data_ro` (`session.py:371`); grantcheck doesn't.
- A read-only exposure is still an exfiltration path, even under `locked` egress, because the model API is itself a channel.
- **Fix:** scan `data_ro` for secrets (H2 rules). Live data there is the declared purpose, so report it as information only.
- **Test:** a session with a `data_ro` dir holding `prod.yaml` with a fake token refuses to start.

**M3. Git credential shapes are missed (shape 16).**
- **Fix:**
  - Change the regex to flag `https?://[^/\s@]+@` (any userinfo on http(s)).
  - Flag `extraheader` and `credential.helper=store`.
  - Read the config of every git dir that `mounts.find_git_dirs` returns, not just `<dir>/.git/config`.
- **Tests:** unit cases for `https://ghp_x@github.com/a/b`, `http.extraheader=AUTHORIZATION: bearer x`, and a submodule's `.git/modules/sub/config`.

**M4. The ack can be given without seeing the findings, and holds across changes the user never sees.**
- At add time, `--i-understand-grant-exposure` records the fingerprint and prints only a **count** (`cli.py:56-59`). The user never sees the list.
- `accept-grant-exposure` re-scans and records whatever is there *now*, with no tie to the refusal the user actually read. It prints the list only *after* recording it (`cli.py:98-107`).
- The fingerprint covers finding *paths* only. So these never re-prompt:
  - an acked `.env` or `prod.yaml` whose content changes from dev to prod values;
  - a new token in the same `.git/config`;
  - new tables in an acked compose data dir.
- **Fix:**
  - The refusal prints the fingerprint, and accept requires it (`--fingerprint X`), refusing if the current scan differs. At add time, print the full list.
  - Fold `(size, mtime_ns, ino)` of each file finding into the fingerprint, keeping the display unchanged.
- **Tests:**
  - Unit: ack a finding, rewrite the file with different bytes, and the session refuses.
  - CLI: `accept-grant-exposure` with a stale fingerprint refuses.
  - CLI: `add --i-understand-grant-exposure` output contains each finding path.

## Low

- **L1. `--with-secrets` can never satisfy an ack.** `_mask_dsts` (`cli.py:75`) always plans with masks on, but a `--with-secrets` run plans with none (`presets.py:106`). Any project with a `.env` then refuses forever, and the suggested command can't fix it. This fails closed, but it invites workarounds.
  - **Fix:** treat the explicit flag as the acknowledgement for the secret-name half of the check.
  - **Test:** a unit test for that path.
- **L2. A growing database re-prompts at every MB.** The live-data finding embeds `{MB}` (`grantcheck.py:129`), so the fingerprint changes as the database grows. That trains you to rubber-stamp the accept.
  - **Fix:** fingerprint the stable part only and keep the size in the display.
- **L3. Data written during a session isn't checked (shape 21).** The agent's own namespace can't be fixed: write that down ("no live service may write into a grant"). For the gate half, run the H1/M1 data rules in the bind-time walk next to N6.
  - **Test:** a gate unit test where a 2 MB `.db` created after start makes a bind of its dir get refused.
- **L4. Exempt names and skipped dirs (shapes 6–7)** pass both layers. The H2 content scan catches the real-secret cases; document the rest.
- **L5. Symlinks across grants (shape 18).**
  - **Fix:** flag a secret-named symlink whose target is inside a grant but not covered.
  - **Test:** `.env -> config/app.txt` (non-empty) gives a finding.
- **L6. Grant symlink retargeted between scan and mount (shape 19).** Only a host process could do this, never the agent. Note it; no fix needed.

**Order I'd fix them in:** H1 (it's the only shape where the gate itself opens access), then H3 (a one-line policy change plus a message fix), H2, M4, then M1–M3.
