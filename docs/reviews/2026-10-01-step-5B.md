## Gaps, ranked

**G1 — HIGH (plausible). Non-canonical request paths bypass the gate's create/exec matching.**
`agentbox/gate.py:554` (`path = unquote(urlsplit(target).path)`) and the `RE`/`RESOURCE` matchers (42-56). The gate `unquote`s but never canonicalizes the path — it does not collapse `//`, resolve `/../`/`/./`, or strip trailing slashes. A body posted to `…/libpod/../containers/create` (or `…//containers/create`) fails every create regex, so `decide` returns it as `"pass"` (586), the body is forwarded **unrewritten and unverified** (no network pinning, no port/privileged stripping, and `verify_created` never runs because the kind isn't a create), and sockguard — which per `docs/decisions.md` does *not* block published ports/host-net/privileged on create — would admit it if it cleans the path the way podman's router does. Net effect: an agent could create a container with a published host port or host network, i.e. exactly what the gate exists to prevent.
- Fix: canonicalize the path once (collapse empty segments, resolve `.`/`..`, drop trailing `/`) and match on that; forward the canonical form, or hard-reject any request whose path isn't already canonical. Do this before the `decide` dispatch.
- Test: unit — `decide("POST","/v5/libpod/../containers/create", …)` with a published-port body must `Deny` (or be treated as a create and rewritten). Integration — same via `curl --unix-socket`, assert nothing is created and no unpinned container appears.

**G3 — MEDIUM (plausible). Leftover bytes after a pass-through request are forwarded to sockguard unparsed.**
`agentbox/gate.py:793-795`: after a non-create request the handler does `upstream.sendall(head+body); if rest: upstream.sendall(rest)`, where `rest` is whatever followed the body in the client's buffer. A pipelined second request (e.g. a privileged/ported `containers/create`) is handed to sockguard without passing through `decide()`, so none of the gate's rewrites or `verify_created` apply. Mitigated today by the forced `Connection: close` (a Go `net/http` upstream drops pipelined bytes after serving one request) and by sockguard's own rules — hence medium, not high — but it's a latent hole that breaks the moment the upstream keeps the connection alive.
- Fix: for non-upgrade requests, never forward `rest`; if `rest` is non-empty, treat it as a protocol error and close. Only forward trailing bytes when `Upgrade` was negotiated (the legitimate exec-start/attach hijack stream).
- Test: unit/integration — send two pipelined requests on one connection where the second is a create with a published port; assert the second is not acted on (nothing created).

**G2 — LOW. Network create is not canonicalized; `NETWORK_FIELDS` is dead code.**
`agentbox/gate.py:91` (defined), `93` (omitted from `CANON`), `559` (`canon=None`), `446-455`. A body like `{"name":"x","INTERNAL":false}` takes the `else` branch of `rewrite_network`, which adds lowercase `internal:true` while leaving the client's `INTERNAL:false` in place; on the wire podman sees two keys differing only in case and may honour the client's `false`. Impact is currently nil — containers and pods are force-pinned to the session network, so nothing ever attaches to an agent-created network — so this is robustness, not a live breach.
- Fix: add `("network", NETWORK_FIELDS)` to `CANON` and pass `"network"` as the canon for `net_create` in `decide`; keep forcing `internal`/`Internal` true.
- Test: `test_gate` — `rewrite_network({"name":"x","INTERNAL":false})` yields exactly one internal key, set true.

**G4 — LOW. Image push, manifest push, login and commit are blocked only by sockguard, not by the gate.**
`agentbox/gate.py:580-586` — these endpoints aren't in `RESOURCE`, so they fall through to `"pass"`; `sockguard.DEV_RULES` (101-122) has no allow rule for them, so the deny-rest catches them. Correct today, but it's single-layer and undocumented as such: the gate's docstring (9-24) enumerates what it rewrites/refuses and never mentions these, so a future `DEV_RULES` edit that adds, say, push for a registry mirror would silently open exfiltration with no gate backstop.
- Fix: make the gate explicitly refuse `*/push`, `/auth`, `*/commit`, `*/export`, `*/manifests/*/push` (defense in depth), and note the reliance in the docstring.
- Test: `test_gate.Scoping` — `decide("POST","/v5/libpod/images/x/push", …)` raises `Deny`.

**G5 — LOW (test gap only). No test asserts `archive`/`top`/libpod-stats are refused on `podman-live.sock`.**
`tests/integration/test_step4_sockguard.py` checks top, host-wide stats and logs, but not `GET/PUT /containers/*/archive` (which would let the observe tier read files out of the live stack). Covered by `DENY_REST`, just unverified.
- Fix/test: add `ARCHIVE_RC` (and a libpod inspect) probe to `test_step4.test_b` asserting a non-zero/403.

## checked and sound

The field-spelling defense that was the point of `bbd81b6` is solid for libpod/compat/volume creates: `strict_loads` + `canonical` + per-kind field checks + `verify_created` reading back what podman stored is genuine defense in depth, and the itest exercises real case-variant bodies end to end. Pull normalization/allowlisting, build query rewriting (namespace-path overwrite, holder re-check, dropped security knobs), exec-session scoping, and the observe-tier inspect/top/stats/logs restrictions all match their design and decisions entries and are tested. The chunked request/response handling on creates is correct.

Doc claims the code does **not** back up:
- `docs/design.md:270` lists the pull allowlist as "(`docker.io`, `ghcr.io`, `quay.io` by default)", omitting `lscr.io`; the code (`sockguard.REGISTRIES`, `gate.cfg["registries"]`) and `design.md:280` both include `lscr.io`. Inconsistent — one of the two design lines is wrong.
- `docs/design.md:283` says exec scoping requires "the project's compose label **or** the session's owner label." The gate's `require_dev` (271-276) requires `agentbox.dev-owner == session` **and** `agentbox.role == dev` only — there is no compose-label path. The code is correctly stricter than the prose; the design text should be narrowed to match (the compose-label clause belongs to the observe/exec tiers, not the dev gate).
- `docs/decisions.md:100` / gate docstring (9-24) present push/export/commit/login as disallowed, but that denial lives entirely in sockguard's deny-rest, not in the gate (see **G4**); the docstring reads as if the gate enforces it.
