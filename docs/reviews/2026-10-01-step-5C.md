# Step 5 audit, part C: lifecycle and tooling

I didn't edit any files or start any containers. One check didn't run: I tried to confirm finding H2 with a throwaway git repo under `/tmp`, and that command needed approval. H2 therefore rests on git's documented defaults, not on a run.

The most serious problems are three high-severity gaps (details below):
- **H1:** a dev-tier build can overwrite any image tag, including the agent images every project uses and the live stacks' images.
- **H2:** the end-of-session scan runs the host's `git` inside repos whose config the agent can write, which can run agent-planted commands on the host.
- **H3:** if the scan crashes, teardown never runs, so the session's dev stack keeps running with internet access through the proxy.

## Gaps, ranked

### High

**H1. Build tags are unrestricted, so a session can poison images.** `agentbox/gate.py:489-527`
- **What it allows:** `podman build -t localhost/agentbox-claude:latest` (or `-t lscr.io/linuxserver/sonarr:latest`, `docker.io/library/busybox:1.36`) replaces an image that later sessions of *every* project use, with that project's files and token mounted. It also replaces a live stack's image on its next restart.
- **Made worse by gc:** `gc_images` keeps the newest image for each tag, so the poisoned image is the one that survives (`session.py:987-992`).
- **Fix:**
  - Refuse a `t` when an image of that name already exists without this project's `agentbox.role=dev` label. Check through `raw_json('/libpod/images/<name>/json')` before forwarding.
  - Refuse registry-qualified names and `localhost/agentbox-*` outright.
  - Have the launcher run agent images by an ID recorded at `make *-image` time, not by tag.
- **Tests:**
  - unit `PullsAndBuilds.test_build_tag_of_a_foreign_image_refused`;
  - itest: `-t localhost/agentbox-omp:latest` and `-t docker.io/library/busybox:1.36` through the gate get a 403, and the image IDs are unchanged.
- This may overlap with whoever audits build fields.

**H2. The scan runs host `git` in repos whose config the agent controls.** `scan.py:27-29, 87-89, 126-130`; `mounts.py:161-176`
- **Why the config is writable:** read-only overlays exist only for git dirs that were present at session start. A repo the agent creates (`git init sub`) has a writable `.git/config`.
- **What it allows:** that config can define `diff.x.textconv` or `filter.y.clean`, plus a `.gitattributes`. At session end, `git show`/`git diff` (textconv is on by default for both) and `git status` (clean filters run on files whose stat changed) then run the agent's command on the host as `vmuser`.
- **It repeats next session:** in later sessions, `scan.snapshot` runs `git status` on that repo at *start*. The overlay is read-only by then, but the content is already malicious.
- `-c core.fsmonitor=false` blocks only one of these vectors.
- **Fix:**
  - Run git only in git dirs recorded at start whose `config`/`config.worktree`/`commondir` bytes are unchanged.
  - Report new or changed repos by path without running git in them.
  - Add `--no-textconv --no-ext-diff`, and set `GIT_CONFIG_NOSYSTEM=1` and `GIT_CONFIG_GLOBAL=/dev/null` for the scan's calls.
  - Replace `git status` with hashing run-later files directly.
- **Test:** `test_scan`: after `snapshot`, create a repo with a textconv driver and a clean filter that each write a marker file, commit, then call `report()`. Assert no marker file exists.

**H3. If the scan raises, teardown never runs.** `session.py:614-618` (no try/finally), `591-601` (catches only `OSError`/`SubprocessError`); `scan.py:28` (`text=True`, strict decoding)
- **Trigger:** the agent commits a file containing Latin-1 bytes. Decoding the `git diff` output raises `UnicodeDecodeError` (a `ValueError`).
- **Result:** proxy, gate, podman service and dev containers all keep running with egress after the session "ends", until the next boot's gc.
- **Fix:**
  - wrap the scan call in `try/finally` so teardown always runs;
  - catch `Exception` in `end_of_session_scan`;
  - pass `errors="replace"` to the scan's subprocess calls.
- **Tests:**
  - unit: patch `scan.report` to raise `ValueError` and assert the run dir is gone and `rm -f` calls were made;
  - `test_scan`: a Latin-1 commit makes `report()` return normally.

### Medium

**M1. Implicitly created volumes are never cleaned up.** `session.py:909` (`rm -f` without `-v`); gate `rewrite_*_container` (`gate.py:327-420`) and `container_violations` (`221-223`) check only bind mounts
- **What it allows:**
  - Anonymous volumes and auto-created named volumes are unlabelled, so they outlive the session.
  - Named-volume references aren't checked at all. Whether another project's or a live stack's volume can be mounted depends on sockguard's owner isolation, which hasn't been verified.
- **Fix:**
  - teardown uses `rm -f -v`;
  - the gate refuses named-volume references unless the volume carries this session's dev labels;
  - the post-create check covers `Mounts` entries of type `volume`.
- **Tests:** itest with an image that declares `VOLUME`, plus `-v abt-x:/d`: nothing labelled or orphaned remains after the session, and `-v <canary volume>:/d` gets a 403. Also add pods and volumes to `leftovers()`.

**M2. `ab kill` and gc skip the scan and destroy the logs.** `cli.py:147-153`; `session.py:903-909` (rmtree of the service dir, which holds `gate.log`, then container removal)
- **What it allows:** exactly the sessions that need review (crashed, or killed from outside) end with no scan and no gate, proxy or sockguard audit trail.
- **Fix:**
  - write the scan snapshot to the run dir as JSON at start;
  - move log-keeping and the scan report into the module-level `teardown()`.
- **Tests:**
  - unit: `prepare()`, then `cli.main(["kill", name])`, then assert `*-gate.log` and `*-scan.log` exist;
  - itest: a SIGKILLed dev-tier session followed by `ab gc`.

**M3. The secret scan only sees commits reachable from HEAD.** `scan.py:119-131`
- **What it allows:** a secret committed on a side branch (or a tag, a note, a stash) is missed, then pushed later with `--all`.
- **Fix:** snapshot `for-each-ref` at start; at the end, scan `rev-list --all --not <start refs>`.
- **Test:** commit on a branch, check out back to the original, and assert it's reported.

**M4. Run-later detection is incomplete.** `scan.py:20-22, 87-89, 147-151, 161`
- **What it misses:**
  - files already dirty at start and edited further;
  - gitignored files: `.envrc`, `.venv/**/*.pth` (both named in the design);
  - scripts that were already executable and got edited;
  - `conftest.py`, `.vscode/settings.json` and `launch.json`, `.github/workflows/*`.
- **Fix:** hash run-later candidates and executable files during the walk at start and end, including ignored files.
- **Tests:** one unit case for each of these.

**M5. Repos created during a session have writable hooks and config.** `mounts.py:161-176` (also the root cause of H2)
- **What it allows:** Tim's later `git commit` in such a repo runs the agent's hooks.
- **Fix:** the scan flags every new git dir prominently ("check `.git/config` and hooks before using git here").
- **Test:** covered by the H2 test.

### Low

- **L1. The lockdown cover list is hand-picked.** `adapters/omp.py:43-44, 384-386`. Any OMP project-settings file isn't covered or tested. Paths created during a session are covered only from the next session (acceptable, since OMP has already started). Fix: confirm OMP's project-config loaders, or cover `.omp/` whole. Test: extend `test_omp_repo_code_does_not_run_in_lockdown`.
- **L2. Proxy-variable injection breaks some creates (functional only).** `gate.py:309-318, 117-123`.
  - A libpod env holding `HTTP_PROXY` gets `http_proxy` added next to it, so sockguard refuses the create for case-variant keys.
  - `canonical()` renames env and label keys that match field names (`HOSTNAME`, `NAME`, `TYPE`, `IMAGE`).
  - Fix: canonicalise schema paths only; skip injection when a case variant is already present. Test: `rewrite_libpod_container({"env": {"HTTP_PROXY": "x", "HOSTNAME": "0.0.0.0"}})` keeps both keys and adds no case-variant duplicate.
- **L3. Images grow without bound on the disk the live services share.** Pulled images and build layers are never removed. Fix: force `layers=false` on builds, and gc removes dangling images carrying session labels. Test: itest image count after two builds.
- **L4. Build cgroups pile up.** The `<session>-build` cgroup dir is never removed. Fix: `rmdir` it in teardown. Test: unit with a fake cgroup root.
- **L5. The scan ignores `mask_skip`.** `scan.py:50-73` walks huge `data_rw` trees at start and end. Fix: pass the skip list through. Test: unit.
- **L6. The leftovers check is narrow.** `harness.py:90-93` checks only containers and networks.
- **L7. gc can race a session that is starting.** A run dir that exists before `session.json` is torn down if gc runs at that moment (`session.py:302-316` vs `958-970`). It fails closed. Fix: skip metadata-less run dirs younger than about 60 s.

## Checked and sound

- **Teardown order:** the service and gate are stopped first, so nothing new can be created while removal runs. Containers, pods, volumes and networks are removed by the session label, which the gate stamps on every explicit create and the post-create check confirms for containers and pods.
- **PID safety:** `_stop` checks the command line and the service dir, so a reused PID is never killed. `services_under` finds the service and the gate even with no run dir. gc spares live sessions and sessions it was told to keep.
- **Restart policies** are stripped and verified after create, so dev stacks stay stopped after a reboot.
- **`gc_images`** filter labels match the gate's stamp, and removal is never forced.
- **Agent NO_PROXY** never includes 10.0.0.2. Missing proxy variables can only fail closed, because the network is internal.
- **Covers:** directories get a read-only tmpfs with `notmpcopyup`, files get a read-only empty file, and the audit requires masks to be read-only. A symlinked cover fails closed.
- **`scanner:allow`** is genuinely ignored. The regex is read from the host hook at report time, matches are cut to 12 characters, and reports are written `O_EXCL|O_NOFOLLOW` with mode 0600.
- **`.claude/` history:** only two commits since bootstrap.
  - `44bfceb` is the bootstrap itself.
  - `6fdad4a` only *adds* checks: `check_git` (`--no-verify`, `-n` clusters, `core.hooksPath`), the `GIT_PRECOMMIT_CHECK_*` block, and 8 block and 6 allow test cases.
  - Nothing was removed or loosened. `settings.json` (hook wiring, deny list) is unchanged since bootstrap, and there are no uncommitted `.claude/` changes.
  - `6fdad4a` mixed guard edits with other work, but it predates decision 4.

## Doc claims the code doesn't back up

1. decisions.md, Step 5 teardown: "dev data does not persist between sessions". Implicitly created volumes persist (M1).
2. `session.py:225` tells the agent "everything is removed when the session ends". Implicit volumes and retagged images remain.
3. design.md worked example: the live stack's volume is "never granted". The gate doesn't check named-volume references (M1).
4. design.md filesystem policy: hooks and config are read-only "for every git directory inside a read-write grant". That holds only for repos that exist at session start (H2, M5).
5. design.md: "The end-of-session report lists which of them changed". This doesn't cover `.venv`, a gitignored `.envrc`, editor tasks other than `tasks.json`, or files already dirty at start (M4).
6. decisions.md and the design's open items: the scan "informs, never blocks", and covers "secrets in the session's commits". In fact it can abort teardown (H3), can run host code (H2), and sees only commits reachable from HEAD (M3).
7. `test_step5_gate` docstring: "everything the session made is gone afterwards". The test only checks containers and networks (L6).
